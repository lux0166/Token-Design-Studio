# Token Design Studio 0.3.0

## Delivered behavior

- Workflow 1.3.0 adds a project-owned dossier, JSON schema, incomplete template and offline validator. Screen, replication, refinement, grill-me and token-only profiles have different evidence requirements. Important unresolved decisions, blocking limitations, failed required checks and unverified blocker/major repairs prevent completion.
- Six additive MCP tools and matching HTTP task endpoints create/read/replace/validate/complete records. A completed record reopens on update; task revisions are independent of theme revisions. Older 11 theme/workflow tools remain available (17 total). Schema and task guide resources are available over HTTP/stdio MCP.
- tasks.json is stored beside the theme store and locked separately. Corrupt task files fail without overwriting them. No migration of the existing studio.json format is needed. Back up both files when moving an existing 0.3 workspace; the migrate command still copies the legacy theme store only.
- Store reuse compares canonical filesystem paths, including macOS /var versus /private/var and Windows junction aliases. Package verification compares real paths and explicitly starts through a symlink/junction. The first macOS CI attempt exposed this issue; the fix is included in both prepared application versions.
- Vietnamese task UI supports creating incomplete dossiers, syncing project JSON, viewing decisions/artifacts/checks/findings, exporting task.json and completing an eligible record. JSON editing captures the revision when editing starts, so background synchronization cannot silently make an old draft overwrite new work.
- token-design-studio-skill is a separate zero-runtime-dependency installer for Codex and Antigravity IDE/app. Its initial tarball is approximately 126 KB compressed. It shares the transaction installer, keeps Codex-only metadata out of Antigravity installs and never changes MCP settings. The full package remains supported.

Files and images stay in the project. Studio checks the supplied records and never reads linked files, fetches artifact URLs, certifies image authenticity or assigns beauty/slop scores. A completed grill-me record does not imply implementation or render verification.

## Browser verification and self-review

Used an isolated production server on port 14488 and output/review-data; no real workspace tasks or tokens were edited. Created a grill-me task through the form, observed two missing requirements and a disabled completion action, synced a fixture dossier, completed it with Enter, then edited it and observed reopening. Escape closed the JSON dialog. Runtime/Log observation during the final interactions returned no errors.

Also opened a JSON draft, updated the task through a separate API request and attempted to save the old draft: the UI reported HTTP 409/current revision, retained the draft and preserved the external criterion after cancel. This verifies that the editing revision remains pinned while the dialog is open. Native AX observations occasionally lagged the DOM during automation; semantic Playwright locators/DOM snapshots were used for the final rechecks. The expected 409 is not an unexpected runtime failure.

At emulated 1440px, document and main client widths equaled their scroll widths; at 390px, document/main client and scroll widths were all 390px. Device emulation was cleared. The browser's screenshot bridge scales/crops emulated captures; the mobile image is a scaled capture, not a pixel-fidelity reference. CDP full-viewport capture timed out, so no full 1440px screenshot claim is made. tasks-desktop.png is the normal browser viewport capture; tasks-incomplete.png shows missing requirements. This is a same-agent self-review, not independent user validation.

Before-code direction: preserve the existing white/green workspace, give completion gaps priority over implementation metadata, and keep the primary actions create/sync/complete. After-render finding: showing an unresolved design-direction placeholder on a grill-me task can confuse its scope; adjusted the panel to display decisions/scope without a screen-direction requirement for grill-me/token-only records.
